# uitest 端参考文档模板（初始化用）

> **用途**：uitest 的各端参考文档（环境信息 + 实战经验沉淀）属于团队私有内容，
> 统一存放于 `references/local/`（已被 `.gitignore` 排除，不入库）。
> 首次使用本 Skill 时，运行 `/setup` 或按本模板在 `references/local/` 下为每个网页端创建一份文档，
> 文件名建议与端对应（如 `pc-admin.md`、`root-admin.md`、`h5-mall.md`，可按自己团队的端命名）。

---

以下为单个端文档的标准结构，复制后按需填写：

```markdown
# uitest 参考文档：{端名称}（私有，不入库）

> 本文件位于 `references/local/`（已被 `.gitignore` 排除），存放本团队真实环境信息与实战沉淀。
> 本端经验持续沉淀，每次测试后按 SKILL.md「第十步」格式追加本节记录。
> 已有记录直接套用，不重复踩坑；新坑与解法验证后补充。

## 一、环境信息

| 项目 | 值 | 说明 |
| :--- | :--- | :--- |
| 测试地址 | `http://{测试环境地址}/` | 登录页/路由说明 |
| 登录账号 | {固定账号 或 "每次询问用户提供，不记录"} | 敏感账号禁止写入文档/记忆 |
| 数据库 | {数据库名}（对应 config 的 database.database） | 只读查询用，禁止写库 |
| 典型页面 | {常测页面清单} | 路由 `#/xxx` |

## 二、页面特性

> 实测后补充：登录方式、常用菜单路由、列表页组件（搜索/筛选/批量操作/导出）特点、
> 上传组件行为、弹窗组件差异等。

## 三、端特有坑点与解法（实战沉淀）

### [功能/场景]
- **现象**：遇到的问题或端特有行为
- **根因**：原因分析
- **解法**：验证有效的解决方案
- **验证**：已用于需求 xxx 验证有效

## 四、安全边界（本端特有）

- {本端不可自动执行的高危操作清单，如：真实支付、推送、删真实数据}

## 五、待积累经验

- [ ] {待确认/待积累的事项}
```

---

**填写建议**：
- 「环境信息」是执行第五步（环境准备）的登录依据，缺失时 AI 会转为询问用户
- 「坑点与解法」按 SKILL.md 第十步格式即时追加，是本 Skill 持续进化的核心
- 通用注入代码（文件注入/MutationObserver/XHR 拦截器）见 `references/common.md`，端文档只记录端特有内容
