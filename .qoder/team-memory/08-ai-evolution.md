# 08 - AI 能力进化与经验沉淀机制（主动发现问题 → 确认后升级）

> 场景：AI 在任务执行中发现重复踩坑、流程缺陷、可复用经验时，如何决定是否沉淀/升级。
> 适用：全部 Skill（testcase-generator / testcase-reviewer / ocr / ui-automation / acceptance-report 等）。
> 沉淀来源：某需求用例更新任务复盘（2026-08-29，文件名斜杠目录化 + review 模式不明确两问题均由用户指出后修复）。

## 一、核心机制（4 步）

AI 不得依赖用户指出问题，任务收尾时主动做一次「能力进化反思」：

| 步骤 | 动作 | 说明 |
|:---|:---|:---|
| 1 | **主动发现问题** | 执行中遇到重复踩坑/流程缺陷/可复用经验（含「记忆已沉淀但 Skill 未固化」场景） |
| 2 | **评估升级价值** | 区分：小范围经验（个人坑点记忆，自动沉淀）vs 需升级进化（Skill SKILL.md 强制规则、团队记忆库、脚本固化） |
| 3 | **抛出确认** | 判断需要升级进化时，先向用户说明「问题现象 + 升级建议 + 影响范围」，用户确认后再执行 |
| 4 | **执行固化** | 确认后更新 Skill 文档/团队记忆/脚本，并在任务报告中注明沉淀结果 |

## 二、关键坑点

1. **坑点记忆对执行约束力不足**：个人坑点记忆（如「文件名含斜杠导致目录化归档」）只能辅助判断，无法阻止执行期踩坑；真正的固化点必须是 **Skill 文档中的强制规则**（如 testcase-generator 输出命名规范「文件名安全化必做」）
2. **「记忆已沉淀但 Skill 未固化」是高频漏网场景**：反思阶段应主动核对——该坑点是否已写入相关 Skill 的 SKILL.md？未写入则属于需升级项，抛出确认
3. **个人偏好不得直接覆盖团队规范**：个人记忆与团队记忆冲突时以团队记忆库为准；个人行为偏好如需团队共享，应写入本目录并提交 git

## 三、落地案例（2026-08-29）

| 问题 | 现象 | 升级动作 |
|:---|:---|:---|
| 文件名斜杠目录化 | 标题含 `/`（如「新增/编辑门店」）被 Windows 解析为目录分隔符，误建嵌套目录 | testcase-generator SKILL.md 输出命名规范新增「文件名安全化（必做）」：`/`、`\` → `、`；误建目录修复指引 |
| review 模式不明确 | testcase-generator 调用 testcase-reviewer 描述未声明「有据直接修正」，需用户人工执行 review | testcase-generator SKILL.md 3 处补充：核查自动执行、有据差异直接双路径修正并同步矩阵、仅歧义项抛待确认 |
